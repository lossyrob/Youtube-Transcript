# Empowering Support to Ship Code with AI

## 🎯 Quick Read (TL;DR)

Lisa Orr shared how Zapier tackled their "app erosion" problem—8,000+ integrations constantly breaking due to third-party API changes—by empowering their support team to ship code with AI assistance. Two parallel experiments converged: (1) enabling support to fix bugs instead of just triaging them, and (2) building "Scout Agent" to generate merge requests automatically. The result? **40% of support app fixes are now AI-generated**, and support team members doubled their velocity from 1-2 tickets/week to 3-4. The key insight: support teams have three superpowers that make them ideal for AI-assisted code fixes—they're closest to customer pain, troubleshooting in real-time with fresh context and available logs, and best positioned to validate that fixes actually solve the customer's original problem. Some support team members have even transitioned to engineering roles through this experience.

**Core Thesis**: Support teams, armed with AI codegen tools, are uniquely positioned to fix customer-facing bugs because they have the freshest context, closest customer proximity, and best validation capability.

**Top 3 Takeaways**:
1. 40% of support app fixes are now generated by Scout Agent, doubling individual velocity from 1-2 to 3-4 tickets/week
2. Support teams have three superpowers for bug fixing: closest to customer pain, real-time troubleshooting with fresh context, and best at validation
3. Scout Agent achieves 75% accuracy on categorization and fixability assessments, with continuous improvement as more tickets become test cases

## 📋 Key Takeaways

### Main Arguments
- **App erosion is a constant, compounding problem**: With 14 years of history and 8,000+ integrations built on third-party APIs, Zapier faces continuous API changes and deprecations that create reliability issues—"it never stops"
- **Backlog crisis required new solutions**: Tickets were coming in faster than they could be handled, creating integration reliability issues, poor customer experience, and even customer churn
- **Support is an untapped resource for bug fixes**: Many support team members already had engineering aspirations and were "unofficially" helping maintain apps—formalizing this created better outcomes
- **AI + support is a powerful combination**: Rather than replacing support or engineering, AI amplifies support's existing context advantage
- **Fresh context matters enormously**: Tickets in real-time have accessible logs and fresh context; the same ticket months later in an engineering backlog may have stale or missing information

### Announcements & Demos
- **Scout Agent**: Zapier's internal AI agent that generates merge requests for support-submitted issues
- **Scout workflow**: Issue submission → categorization → fixability assessment → MR generation → support review/testing → optional adjustment requests → engineering review
- **Rapid iteration feature**: Support can now chat with Scout Agent directly in GitLab to request tweaks, eliminating the need to pull code locally to make adjustments
- **GitLab CI/CD pipeline integration**: Scout runs three phases (plan, execute, validate) within GitLab pipeline to generate merge requests

### Technical Details
- **Tools**: Scout Agent uses Scoutm APIs (invested in a year ago) orchestrated within GitLab pipeline, plus Cursor SDK
- **Evaluation metrics**: 75% accuracy for both categorization and fixability assessment
- **Workflow automation**: Entire process is orchestrated by Zaps (Zapier's automation platform)—"we do a ton of dog fooding"
- **Three-phase pipeline**: plan → execute → validate for merge request generation
- **Guardrails**: Started with just 4 target apps, engineering review required for all merge requests from support
- **Categorization system**: Issues are first categorized, then assessed for fixability before code generation begins

## 🔮 Implications & Predictions

**For Developers**: 
Consider that the best person to fix a bug might not be an engineer—it might be whoever has the freshest context. Build tools that let non-engineers contribute code safely with proper guardrails (limited scope, required review, automated testing).

**For AI Tool Builders**: 
The "Scout Agent" pattern—AI generating code from support tickets with human review—is replicable. The key differentiator is tight integration with existing workflows (Zaps, GitLab, Jira) rather than requiring new processes.

**For Engineering Leaders**: 
This model could significantly reduce the burden on engineering teams while actually improving fix quality (fresher context, better validation). Consider which parts of your backlog could be handled by support + AI rather than waiting in engineering queues.

**Contrarian/Surprising Takes**: 
The talk challenges the assumption that code changes should only come from engineers. Zapier demonstrates that with proper guardrails (scope limits, review requirements, AI assistance), support teams can safely ship production code—and potentially do it better for certain bug classes due to their context advantage.
